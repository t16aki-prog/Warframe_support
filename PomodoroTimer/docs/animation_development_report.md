# 猫のアニメーション開発に関する総合レポート

## 1. 発生していた問題とその原因

### なぜ「寝ている姿」はできて、「活動している姿」はできなかったのか？
- **寝ている姿（sleep）が上手くいっていた理由**:
  元々手描きで作られたベース画像（`cat_sleep.png`）が存在し、着色プログラム（`natural_cat_generator.py`）もその座標（「このピクセルが目」「ここがお腹」）に精密に合わせて作られていたためです。
- **活動している姿（dash, play等）が失敗していた理由**:
  活動中の姿には元画像がなかったため、AIで新しく生成しました。しかし、AI生成の猫はちびキャラ（Chibi）風で元の手描き猫と頭身・形状が異なっていました。それを従来の座標固定型着色プログラムに無理やり通した結果、「目があるはずの場所にお腹がある」というズレが起き、体の横に巨大な目が描かれたり四角い白枠ノイズが残るバケモノ状態になっていました。

### なぜデバッグ画面（debug_viewer.py）では正常に見えていたのか？
初期設定の猫が「白猫（white）」だったためです。白猫は全体を白く塗るだけなので座標のズレが目立たず綺麗に見えていましたが、本編（pomodoro.py）で15種類の猫が同時に出たことで黒猫や三毛猫のバケモノ化が露呈しました。

## 2. これまでに実施した修正・改善内容

- お部屋の背景画像（`room_bg.jpg`）を白と50%ブレンドし、淡く明るいパステルトーンに調整しました。猫たちやUIがくっきりと見やすくなっています。

## 3. 今回実施した改修・実装内容（4大課題の完全達成）

### ① 3秒ごとの動作・位置切り替えサイクルの見直しと再実装（`core/cat_ai.py`）
- **明確な交互サイクルの確立**:
  - `walk` / `dash`（移動）は約3秒間（約60フレーム）持続して目標地点へ移動。
  - 到着時に周囲の猫や家具を判定し、必ず静止アクション（`sit`, `groom`, `stretch`, `play`）へ遷移。
  - 静止アクションは約3秒間その場で持続し、終了時に必ず次の移動（`walk`, `dash`）へ遷移。
  - 「3秒移動 ➔ 3秒別ポーズ ➔ 3秒移動」という小気味よいテンポで猫たちが部屋中を生き生きと巡るようになりました。
- **壁際スタック防止**: 移動方向に部屋の中心への軽いバイアスを付与し、画面端で引っかからない自然な自律移動を実現。

### ② プログラムによる画像の変形（歪み）処理の完全撤廃（`scripts/natural_cat_generator.py`）
- プログラム側で `rotate`（回転）や無理な `resize`（押しつぶし）をかけていた処理を全廃。
- すべて専用のクリーンな画像コマ割りによるパラパラアニメーションに統一し、スプライトを全15毛柄で再生成しました。

### ③ 猫の同一柄（重複）制限と状態維持（`ui/tabs/cafe_tab.py`, `pomodoro.py`）
- **同一柄制限**: カフェ画面上に同じ柄の猫が2匹以上出ないよう厳格に保証（1柄につき1匹）。
- **個体の状態維持**:
  - タイマー開始/停止時に猫オブジェクトを破棄・再生成するのを廃止。
  - タイマー停止時はその場で `sleep`（眠る）、タイマー開始時はその場で目覚めて動き出すシームレスな状態遷移を実現。

### ④ ローカルアプリ（Python/Tkinter）の起動速度の高速化（`pomodoro.py`）
- **オンデマンド・ロード（遅延ロード & キャッシュ）**:
  - アプリ起動時は解放済みの猫のみを初期ロード。
  - 未解放の猫はショップでのプレビュー時や購入時に必要な分だけ遅延ロード＆メモリキャッシュ。
  - 起動時の画像デコード負荷を大幅に削減し、起動速度を劇的に高速化しました。

## 5. 課題対応完了記録

### 1. タイマースタートしても猫の絵が動くときの絵（活動スプライト）に変わらない不具合の修正【完了】
- **原因の特定**:
  - `pomodoro.py` の `animate_loop` 内で `self.canvas_w` / `self.canvas_h` を参照していたが、`PomodoroApp` クラスのインスタンス変数として未定義だったため、1フレーム目（`anim_tick == 1`）のライティング処理で `AttributeError` が発生。
  - ループ末尾の `self.root.after(16, self.animate_loop)` がスキップされ、アニメーションループ自体が起動直後に完全停止していた。
- **実施した修正**:
  - `PomodoroApp.__init__` で `self.canvas_w = 480`, `self.canvas_h = 270` を確実に初期化。
  - `animate_loop` のループ再帰呼び出しを `finally` 節に配置し、予期せぬエラーが発生した場合でもアニメーションループが恒久停止しないよう堅牢化。
  - タイマー開始時に各猫が即座に目覚めて活動ポーズ（`sit` または `walk`）へ遷移し、アニメーションループ側でもスプライト画像が即座に更新・フォールバックされる処理を確立。
### 2. ポーズ遷移時（じゃれる・毛づくろい等）に黒猫化する不具合の修正【完了】
- **原因の特定**:
  - `chibi_cat_generator.py` が「白猫ベース画像（RGB > 150）」のみを対象に着色していたため、暗いベース画像だった `cat_play.png`（じゃれる）および `cat_groom.png`（毛づくろい）が着色されず、全毛柄で黒猫のまま出力されていた。
  - これにより、茶トラや白猫がじゃれあい・毛づくろいアクションに入った瞬間黒猫へ変化し、画面上に黒猫が複数匹重複しているように見えていた。
- **実施した修正**:
  - `scripts/chibi_cat_generator.py` に動的明度解析を導入。ベース画像が暗い場合でも輪郭とボディを正確に分離し、15毛柄（茶トラ・三毛・白猫・シャム等）の固有カラーと模様を適用できるようアルゴリズムを刷新。
  - `scripts/regenerate_all.py` を実行し、全15毛柄×全40ポーズのスプライトを再生成・同期。
- **検証結果**:
  - 全毛柄で `sit`, `sleep`, `walk`, `dash`, `groom`, `play`, `stretch`, `pounce` の全モーションにおいて一貫した毛色が保持されることを確認完了。
