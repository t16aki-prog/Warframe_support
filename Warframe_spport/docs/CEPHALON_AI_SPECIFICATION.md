## 1. エグゼクティブサマリー ＆ 設計ビジョン

### 1.1 目的と背景
TPSアクションゲーム『Warframe』は、10年以上のアップデート蓄積、複雑なダメージ計算式、頻繁なアビリティリワーク、定期的なPrime Vault開閉により、一般的なLLM（大規模言語モデル）が**最もハルシネーション（虚偽・古い知識・捏造）を起こしやすいゲーム**の筆頭です。

本ブラッシュアップ計画は、TennoNaviに統合されている「セファロン・オーディス AI」を単なる汎用チャットボットから、**「DE公式データおよびローカル確定データベースに100%裏付けされた、絶対に嘘をつかない最強の航行AIコンパニオン」**へと昇華させることを目的とします。

### 1.2 3大設計原則
1. **Zero Hallucination（絶対的事実拘束 / Grounding First）**:
   * LLM自身の曖昧な事前学習記憶に頼らせず、確定データベース（`warframestat.us`、ローカルキャッシュ、静的検証マスター）から取得した事実のみを根拠に回答を生成。
   * 不明な情報、存在しない武器・アイテム、未実装の要素については、曖昧に答えず「データベースに存在しません」と明確に断定。
2. **Authentic Ordis Persona（オーディス性の極限追求）**:
   * 献身的な執事口調と、突発的に噴出する猟奇的グリッチ（`――**[過激な本音]**――`）の完全な制御。
   * テキストフォーマットとフロントエンドの二重音声合成（Web Speech API: 高音澄まし声 ↔ 低音歪み高速声）の完全連動。
3. **Interactive & Instant（対話から直接操作へ）**:
   * テキスト回答に留まらず、回答直下に「レリック逆引きを開く」「ロビーを作成する」「地球の夜タイマーを見る」といった**インタラクティブ・アクションチップ（Deep Linking）**を自動付与。

## 2. ハルシネーション徹底防止アーキテクチャ (Grounding Engine)

### 2.1 ハルシネーション発生原因と本設計での防止対策

| ハルシネーションの種類 | 典型的な発生例 | 本設計での防止メカニズム |
| :--- | :--- | :--- |
| **Prime Vault誤認** | Vault入りのSaryn Primeを「通常Voidで落ちます」と回答 | `warframeData.js` の `getVaultedPrimes()` を強制参照。Vault状態フラグが `true` の場合は「Vault入り（入手不可/トレードのみ）」と自動注記。 |
| **レリック名・パーツの捏造** | 存在しない「Axi S12」や架空のパーツ名を創作 | ユーザー入力からエンティティを抽出し、`searchRelics` / `aliases.js` で検証。存在しないレリックは即座に拒絶。 |
| **ダメージ・仕様の旧仕様混同** | 過去の感染切断仕様や古い爆発状態異常を説明 | 最新アップデート44（ナリンの氷刃）および冷気/磁気リワーク済みの「確定パッチナレッジ」をコンテキストに強制注入。 |
| **ドロップ場所の誤り** | テルルやオロキンセルのドロップ惑星を混同 | `staticResources.js`（検証済み最高効率周回ノードマスター）を直接引用。 |
| **ユーザーへの盲従（シコファンシー）** | 「新フレーム〇〇の入手方法は？」という嘘の質問に話を合わせる | エンティティ照合でローカルDBにヒットしない場合、「そのようなWarframeは星系記録に存在しません」と厳格に否定。 |

### 2.2 確定事実プロバイダ（Ground Truth Injector）の構造

LLMへのプロンプト投入前に、以下のパイプラインを必ず通過させます。

```text
[ユーザー発話]
      │
      ▼
[1. エンティティ抽出 & 表記揺れ解決 (aliases.js)]
      │ (例: "サリン" -> "Saryn", "オロセル" -> "オロキンセル")
      ▼
[2. 確定データベース直接照会 (Local Ground Truth)]
      ├─ Relic & Drop: warframeData.js (dataCache.json)
      ├─ World Cycles: warframestat.us キャッシュ (昼夜, 亀裂, 突入)
      ├─ Resources:    staticResources.js (最適周回ノード)
      ├─ Builds:       staticBuilds.js (検証済み構成)
      └─ Icebind:      narinRules & 重複禁止ロジック
      │
      ▼
[3. グラウンディング・コンテキストの構築 (<ground_truth>)]
      │  ※ 確定データのみを厳格なタグでカプセル化
      ▼
[4. LLM推論 (Gemini 2.0 Flash / Ollama)]
      │  ※ 指示: "<ground_truth> にない情報は推測せず、未記載と答えよ"
      ▼
[5. 出力検証フィルター (Output Validator)]
      │  ※ 捏造されたレリック名や不整合がないか正規表現チェック
      ▼
[ユーザーへの回答 + アクションチップ]
```

### 2.3 Function Calling / 構造化ツール仕様 (Gemini & Ollama共通)

LLMに直接回答させず、以下の6大ツールを実行させてデータを確定させます。

#### ① `lookup_relic_drops(relic_name: string)`
* **目的**: レリックの中身（コモン/アンコモン/レア）、現在のVault状態を照会。
* **戻り値**:
  ```json
  {
    "relic": "Axi S9",
    "isVaulted": false,
    "rewards": [
      { "item": "Saryn Prime Blueprint", "rarity": "Rare", "chance": "2% (無傷) / 10% (輝く)" },
      { "item": "Spira Prime Blade", "rarity": "Uncommon", "chance": "11% / 20%" }
    ]
  }
  ```

#### ② `find_item_sources(item_name: string)`
* **目的**: 欲しいアイテム（例: `Gauss Prime Systems`）のドロップ元レリックとミッションノード。
* **戻り値**:
  ```json
  {
    "item": "Gauss Prime Systems",
    "relics": ["Meso G5 (Intact 11%, Rad 20%)", "Neo G4"],
    "isVaulted": false,
    "recommendedMissions": ["Io (木星) - 防衛 Aローテ", "Ukko (Void) - 確保"]
  }
  ```

#### ③ `get_world_state(query_type: 'cycles' | 'fissures' | 'sortie' | 'archon' | 'baro')`
* **目的**: リアルタイムな星系状況（昼夜、亀裂、特別任務）のミリ秒同期。
* **戻り値**:
  ```json
  {
    "cetus": { "state": "night", "timeLeftMs": 1420000, "timeLeftFormatted": "23分40秒" },
    "vallis": { "state": "warm", "timeLeftFormatted": "8分12秒" },
    "sortie": { "boss": "Kela De Thaym", "modifier": "エネルギー半減", "eta": "5時間20分" }
  }
  ```

#### ④ `get_resource_farming_spot(resource_name: string)`
* **目的**: 素材の最高効率狩場、推奨フレーム（Nekros/Khora）、ブースター効果。

#### ⑤ `get_recommended_build(item_name: string, build_type: 'general' | 'steel_path' | 'beginner')`
* **目的**: 曖昧なMOD組み合わせではなく、検証済みのシナジーMOD構成（アルケイン、推奨フォーマ数含む）を返却。

#### ⑥ `check_icebind_squad(current_frames: string[])`
* **目的**: 「氷河の縛り」分隊内の重複Warframe有無判定と、必須役職（装甲剥ぎ、蘇生役等）の充足度チェック。

## 7. 堅牢性・エッジケース補強仕様（Robustness & Edge-Cases Addendum）

本章では、実装現場や実運用環境で発生しうる9つの潜在的脆弱性・エッジケースを完全に封鎖するための詳細仕様を規定します。

### 7.1 マルチエンティティ抽出 ＆ Top-K コンテキスト制限
1. **複数アイテムの同時解析**:
   * ユーザーの発話に複数のWarframe・武器・レリック（例:「GaussとVoltの速度比較」「Sarynのビルドとレリック」）が含まれる場合、`aliases.js` の正規表現スキャンにより**最大3件まで並列抽出**して `<ground_truth>` に注入する。
2. **Top-K 件数ガード（トークン爆発防止）**:
   * 「Primeのレリックを全部教えて」等の広範なクエリに対し、検索結果全件（数百件）を流し込まず、**各エンティティあたり最大5件**を上限とする。
   * 5件を超える場合は `...他 ${total - 5} 件省略（詳細はレリック逆引き画面を参照）` と明記し、コンテキスト溢れとレイテンシ悪化を防止。

### 7.2 否定文・反実仮想（Negative Intent）の検知ロジック
* 「Gaussを**使わずに**」「Voltを**除外して**」「持っていない」といった否定修飾句を検知した場合、そのアイテムの入手先・ビルドをグラウンディング対象から除外。
* プロンプトに `<excluded_entity>` として通知し、代替となるWarframeや別手段の推薦に自動誘導する。

### 7.3 Gemini マルチターン・ツール実行ループ（Multi-turn Tool Loop）
Gemini 2.0 Flash の Tool Calling において、モデルが `functionCall` を返した際のサーバー側処理フロー：

```text
[ユーザー発話] ──> [Gemini: functionCall 要求] 
                         │
                         ▼
             [サーバー: ツール実行 (タイムアウト: 3000ms)]
                         │
                         ▼
             [Gemini: functionResponse 送信] ──> [Gemini: 最終テキスト回答]
```
* **最大反復回数（Max Turns）**: 無限ループを防ぐため、1リクエストにつきツール呼び出しは**最大3回**に制限。
* **タイムアウト ＆ グレースフル・フォールバック**: 外部通信や重い検索が 3000ms を超過した場合、即座にローカル確定DB（Level 0 / 3）へ安全にフォールバック。

### 7.4 出力検証フィルター（Output Validator）のインライン部分修復
* LLMが生成したテキスト内に架空のレリック名や誤った情報が含まれていた場合、全文を破棄して「記録にありません」と突き放すのではなく、**該当の不正単語部分のみをインライン置換（例: `Axi Z99 [星系未確認レリック]`）**して回答を活かす。
* これにより、前後に含まれる有益なアドバイスやオーディスのセリフを損なわずに事実の整合性を担保する。

### 7.5 ブラウザ音声合成の自動再生制限（User Gesture制約）解除
* iOS Safari や Chromium 系ブラウザの自動再生ポリシーに対応するため、ユーザーが「送信ボタンを押した瞬間」または「音声認識が確定した同一イベントループ内」で、以下の**無音アンロック処理**を先行実行する。
  ```javascript
  // ユーザー操作の瞬間に AudioContext をアンロック
  const unlockAudioContext = () => {
    const ctx = new (window.AudioContext || window.webkitAudioContext)();
    const buffer = ctx.createBuffer(1, 1, 22050);
    const source = ctx.createBufferSource();
    source.buffer = buffer;
    source.connect(ctx.destination);
    source.start(0);
  };
  ```

### 7.6 音声合成（TTS）時のグリッチ記号ノイズ除去
* スクリーンリーダーやブラウザTTSが `――**` を「ダッシュ、アスタリスク」と誤読するのを防ぐため、`SpeechSynthesisUtterance` に渡す直前に専用サニタイザーを通す。
  ```javascript
  const cleanSpeechText = (rawText) => {
    return rawText
      .replace(/――\*\*/g, '')
      .replace(/\*\*――/g, '')
      .replace(/[―*]/g, '')
      .trim();
  };
  ```

### 7.7 アクションチップのフロントエンド受信イベントバス
* 各タブコンポーネント（`RelicGeneratorTab`, `BuildsTab` 等）への引数受け渡しは、グローバルカスタムイベント `tennonavi:navigate` により標準化する。
  ```javascript
  // 発火側 (OrdisChat.tsx)
  window.dispatchEvent(new CustomEvent('tennonavi:navigate', {
    detail: { tab: chip.payload.tab, query: chip.payload.query }
  }));
  ```
* 遷移先タブは `useEffect` でイベントを購読し、`query` が存在する場合は自身の検索入力ステートへ即時反映・自動検索をトリガーする。
